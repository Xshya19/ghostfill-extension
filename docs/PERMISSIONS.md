# Permission rationale

This table describes the default full manifest. Source references are provided so a reviewer can independently inspect each use. The restricted temporary-email-only manifest is available only through the explicit `npm run build:public` commands.

| Permission or access | Current purpose                                                                                                                                                                          | Scope and verification before narrowing                                                                                        |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `activeTab`          | Supports user-initiated work in the current signup tab.                                                                                                                                  | Re-test popup, keyboard shortcut, and context-menu actions.                                                                    |
| `storage`            | Stores settings, active temporary-email state, inbox state, and session routing in `src/services/storageService.ts`.                                                                     | Core feature; test restart and clear-data behavior.                                                                            |
| `clipboardWrite`     | Copies generated addresses, passwords, and user-selected OTPs through `src/services/clipboardService.ts`.                                                                                | Could become an explicit optional permission only after copy flows are re-tested.                                              |
| `contextMenus`       | Creates GhostFill field actions in `src/background/contextMenu.ts`.                                                                                                                      | Optional feature; test menu rebuild and all actions before removal.                                                            |
| `alarms`             | Drives polling, health checks, service-worker recovery, and encryption rotation in `src/background/pollingManager.ts`, `src/background/serviceWorker.ts`, and `src/utils/encryption.ts`. | Core reliability feature; test suspension and restart behavior.                                                                |
| `notifications`      | Shows opt-in operational notifications in `src/background/notifications.ts` and `src/services/otpService.ts`.                                                                            | Candidate for an optional permission only with fresh notification preference tests.                                            |
| `offscreen`          | Supplies clipboard and DOM-parser work from `src/background/offscreenManager.ts`.                                                                                                        | Test copy and message parsing before changing.                                                                                 |
| `tabs`               | Routes OTPs to signup tabs, tracks activation tabs, and opens user-approved links in `src/background/pollingManager.ts` and `src/services/linkService.ts`.                               | Core cross-tab workflow; test two simultaneous signups and activation routing.                                                 |
| `cookies`            | Sets provider cookies for the YOPmail integration in `src/services/emailServices/yopmailService.ts`.                                                                                     | Retained because a supported temporary-email provider calls it. Test that provider before removal or making it optional.       |
| `identity`           | Runs Google/Gmail OAuth sign-in and token management through `src/services/gmailApiService.ts` and `src/services/gmailConnectionService.ts`.                                             | Restricted account access; keep the Gmail consent screen, OAuth client, sign-out path, and token revocation behavior reviewed. |
| `scripting`          | Performs the user-initiated Gmail session/profile detection path in `src/services/gmailConnectionService.ts`.                                                                            | Keep gated by the full profile and review every injected function before broadening its use.                                   |

The default package requests `identity` and `scripting` because it is the full profile. The restricted package does **not** request them and is built explicitly with `npm run build:public` or `npm run build:public:zip`.

## Host and content-script access

The default full manifest grants network access to the listed temporary-email providers plus Google, Microsoft, and Zoho hosts retained by the full provider integration. The restricted public profile removes the real-mail hosts.

The content script still matches `http://*/*` and `https://*/*`, runs in all frames, and has curated exclusions for major banking, brokerage, password-manager, and Chrome Web Store domains. Broad matching is required by the current generic signup-form and OTP-field detection architecture. It is a material privacy limitation: an installed extension can run its content script on other eligible websites. Do not remove the exclusions without a documented replacement and a test pass.
